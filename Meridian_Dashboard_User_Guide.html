Meridian Dashboard — User Guidev2 · Order Flow Intelligence layer

How to read the engine. In the right order.

A field-by-field walkthrough of the Meridian OFI Dashboard — the Order Flow Intelligence layer built on top of Meridian Engine v2. Every panel, every label, and every button, explained once, with the special color format that maps each order-flow read to its own shape and color.

The one-paragraph mental model

The engine is a confirmation filter, not a signal generator. You read it in this order — Regime → 3-Gate → Lattice → Order Flow → Liquidity → Signal — and it only prints a trade when all the gates line up on one side. Most bars will show grade — and no signal. That's the engine honestly saying "no aligned setup", not a bug.

Pools form on liquidity sweeps and stacked imbalances. Each has a magnet that decays ×0.92/bar and re-charges on reaction. Top magnet = strongest active pool — that's where TP3 gets aimed. Price is pulled toward these.

Read it directionally, not literally: the map shows where opposing liquidity is sitting relative to price, so you know the most likely magnet the engine is aiming TP3 at.

2 · How to set up trades

Broker — paper first, always.

The dashboard wires to Alpaca for paper bracket orders. One-time setup, then a one-click execute from the signal surface.

⚙

Setup & the trade flow

Key once, click per signal.

PAPER · connected
🔑

One-time: ALPACA_API_KEY / ALPACA_SECRET_KEY in backend/.env (already wired locally with paper keys). Badge reads PAPER · connected.

To trade

StepWhat happens
1 · SignalWait for a signal → the Signal panel shows ▶ Execute paper bracket.
2 · ClickPlaces an Alpaca bracket: market entry + TP1 limit + SL stop as an OCO.
3 · ResultShows order id + both legs + live-anchored or delayed (market closed).
4 · PositionsPositions button → Positions tab (close buttons) + Orders tab (bracket legs with live status).
5 · CancelCancel via the link under a just-placed order.
◎

Sizing: default $5,000 notional (qty = $5k ÷ entry); override via API qty/notional. Live re-anchoring: when tape is ●LIVE, entry/SL/TP1 re-anchor to the live mid, preserving R:R distances; when closed it uses delayed levels and says so.

⚠

Going live (real money): two gates, both required — ALPACA_LIVE=1 in env and confirm="LIVE" in the request. No accidental real orders. TP2/TP3 are never auto-executed — journal-only scale targets.

4–5 · Journal & Watchlist

The other two buttons.

Journal scores every signal forward-only; Watchlist pins the symbols you keep coming back to.

Journal

Auto-capture, forward-only

Every signal is captured automatically (forward-only), scored CONFIRM/BREAK, and surfaced as Confirm % and Profit Factor (R). Export to JSON/CSV.

Watchlist

Pin what you watch

☆ pins the current symbol; chips jump to it or remove it. Stored in localStorage — nothing leaves your browser.

Both together

Study → trade → review

Watch a symbol, let the engine grade it, trade the paper bracket when it aligns, then read the journal to see if the path confirmed or broke.

6 · Honest limitations

What this engine isn't.

Stated plainly, so you can calibrate your trust.

·

Delayed data — Polygon OHLCV is delayed; the tape (IEX) is fresher but still not tick-perfect.

·

Stacked imbalance = the ·px proxy — native diagonal footprint isn't available from OHLCV aggregates.

·

HTF bias omitted — the higher-timeframe context flag is off.

·

VWAP daily-anchored — no exchange-session feed, so it anchors to the day.

·

Stocks only — futures need a separate Polygon entitlement.

·

Paper account = $100k / $400k buying power — not real capital.
